01

Основы визуала и дизайн-мышления

Прежде чем открыть Figma — нужно "поставить глаз". Цвет, типографика, композиция и сетки — фундамент, без которого всё остальное рассыпается. Эта фаза формирует дизайнерское мышление.

🔤Типографика
📐Композиция и сетки
📏Пространство и отступы
👁️Визуальная иерархия
🖼️Анализ реальных UI

Домашние задания по неделям
Неделя 1 Цвет — теория и практика ▼
📖
теория
Посмотреть плейлист DesignCourse "Color in UI Design" (3–4 видео, ~40 мин). Записать: что такое первичные/вторичные цвета, тёплые/холодные, контраст.
✏️
практика
Создать 5 цветовых палитр в Khroma. Для каждой написать: какое настроение передаёт, подойдёт ли для детского/медицинского/игрового приложения.
✏️
практика
Найти 3 приложения (любых) с разными цветовыми стилями. Для каждого: выписать главный цвет, вторичный, фоновый. Почему именно эти цвета выбраны?
Неделя 2 Типографика — читабельность и иерархия ▼
📖
теория
Посмотреть 2–3 видео DesignCourse о типографике. Записать: serif vs sans-serif, что такое line-height, letter-spacing, размерная шкала (H1/H2/body/caption).
✏️
практика
Открыть Google Fonts. Выбрать 3 пары шрифтов: один для заголовков + один для текста. Для каждой пары написать: в каком типе приложения это смотрелось бы хорошо.
✏️
практика
Сделать скриншот 3 разных сайтов и разметить текст: H1 / H2 / body / caption. Проверить — везде ли чёткая иерархия? Что бы ты улучшила?
Неделя 3 Композиция и пространство ▼
📖
теория
Видео DesignCourse "Spacing & Layout" + прочитать 2 статьи из Refactoring UI (можно бесплатные из Twitter/X автора @adamwathan).
✏️
практика
Взять скриншот любого экрана телефона (не дизайнерского — например скрин системного меню). Нарисовать поверх него маркером (или в Paint/Canva) как бы ты расставила отступы. Что важнее и должно быть крупнее?
🚀
мини-проект
В Canva создать простую карточку товара (любого). Применить: чёткая иерархия текста, отступы, цвет. Сохранить и сравнить с карточкой в реальном магазине (напр. Rozetka).
Недели 4–6 Насмотренность + анализ реальных UI ▼
✏️
практика
Каждый день 10 минут: просматривать Dribbble или Mobbin. Сохранять то, что нравится в отдельную папку. К концу 3 недель — 60+ референсов. Периодически пересматривать и думать: почему нравится именно это?
✏️
практика
Разобрать 5 реальных экранов из Mobbin: написать для каждого — цветовая схема, размер кнопок, как расположен контент, что привлекает взгляд первым.
🚀
итог фазы
Создать мудборд в Pinterest: 30+ изображений на тему "мой идеальный мобильный дизайн". Разбить на секции: цвет, типографика, компоненты. Это будет твой визуальный язык.

Домашние задания по неделям
Недели 7–8 Первое знакомство — фреймы, шейпы, текст ▼
📖
теория
Пройти первые 4 урока официального курса Figma. Параллельно — создать аккаунт, изучить интерфейс: левая панель (слои), правая (свойства), панель инструментов.
✏️
практика
UI Copy Challenge — найти любой экран телефона и воссоздать его в Figma 1:1. Важна точность: отступы, цвета, шрифты. Начни с простого — экран калькулятора или "О телефоне" в настройках.
Недели 9–10 Auto Layout — главная суперсила Figma ▼
📖
теория
Посмотреть видео Mizko по Auto Layout (1–1,5 часа). Цель: понять как работает gap, padding, fill/hug/fixed и вложенные авто-лейауты.
✏️
практика
Построить карточку товара (картинка + название + цена + кнопка) используя ТОЛЬКО Auto Layout. Проверить — если менять длину текста, карточка должна растягиваться правильно.
✏️
практика
Построить навигационное меню (навбар) с лого, 4 пунктами и кнопкой. Auto Layout + Constraints чтобы он правильно тянулся по ширине.
Недели 11–12 Компоненты, варианты, стили ▼
📖
теория
Пройти уроки официального курса Figma по Components и Variants. Понять: главный компонент vs инстанс, зачем нужны варианты, как делать кнопку со всеми состояниями.
🚀
мини-проект
Создать мини-библиотеку компонентов: кнопка (3 размера × 3 состояния), input-поле (normal/focus/error), иконка-аватар. Правильно назвать всё в слоях: "Button/Primary/Large/Default".
Недели 13–14 Прототипирование и анимации переходов ▼
📖
теория
Изучить прототипирование в Figma: Connections, Triggers, Transitions. Smart Animate — для плавных переходов.
🚀
проект
Первый полноценный прототип: 5 экранов мобильного приложения (любого) с рабочими переходами. Сделать так, чтобы можно было кликать и переходить между экранами — покажи кому-нибудь и получи обратную связь.
✏️
практика
Скачать Untitled UI Kit, открыть в Figma. Изучить структуру: как организованы компоненты, стили, переменные. Попробовать использовать 5–6 компонентов в своём макете.
Недели 15–16 Итоговый проект фазы: копия реального приложения ▼
🚀
итог фазы
Выбрать реальное приложение (Spotify, Duolingo, Notion — что нравится) и воссоздать минимум 8 экранов в Figma. Условия: правильная структура слоёв, компоненты, Auto Layout, прототип с переходами. Это НЕ должно быть идеально — важна практика, а не результат.
03

UX — логика, исследования и пользовательский путь

UX — это не "как выглядит", а "как работает". Эта фаза учит думать о пользователе: зачем он открыл приложение, где заблудится, что его расстроит. Без UX — красивый дизайн просто не работает.

Домашние задания по неделям
Недели 17–18 Research — разобраться в проблеме ▼
🚀
проект
Придумать идею приложения (реши реальную проблему подростков: расписание, общение, хобби, учёба). Провести мини-интервью с 3 людьми: "Расскажи как ты сейчас решаешь эту проблему?" Записать главные инсайты.
✏️
практика
Создать Empathy Map (FigJam): что пользователь думает / чувствует / говорит / делает. Заполнить на основе интервью.
✏️
практика
Создать 2 персоны (User Persona): имя, возраст, цели, боли, сценарии использования. В FigJam или Figma. Они должны быть реалистичными — взяты из реального интервью.
Недели 19–20 User Flow и информационная архитектура ▼
✏️
практика
Для своего приложения: нарисовать User Flow от открытия до выполнения главного действия. Использовать правильные обозначения: ромб = решение, прямоугольник = экран, стрелки = переходы. Инструмент: FigJam.
✏️
практика
Разобрать любое реальное приложение (Telegram, Nova Poshta, Instagram) — попробовать нарисовать его User Flow для одного ключевого действия. Сравнить насколько это сложно или просто.
Недели 21–22 Wireframing — скелет интерфейса ▼
📖
теория
Посмотреть 2–3 видео Laith Wallace о wireframing. Понять разницу: Lo-fi (схема на бумаге) vs Mid-fi (серые блоки в Figma) vs Hi-fi (полноценный дизайн).
✏️
практика
Нарисовать от руки на бумаге 6 экранов своего приложения. Только блоки и стрелки — никакого цвета. Цель: проработать логику, а не красоту.
✏️
практика
Перенести бумажные вайрфреймы в Figma как Mid-fi: серые блоки, заглушки для текста, кнопки без стиля. Показать другу или члену семьи — понимают ли они что здесь происходит?
Недели 23–24 Usability Testing — проверка логики ▼
🚀
итог фазы
Провести usability test Mid-fi прототипа с 3 людьми. Задание: "Попробуй выполнить [конкретное действие] в этом приложении, я буду наблюдать". Не помогать, только наблюдать где они "застревают". Записать 5 проблем и исправить вайрфреймы.
🤖
AI-задание
Использовать ChatGPT или Claude: "Ты UX-эксперт. Вот описание моего приложения [описание]. Найди 5 потенциальных проблем с пользовательским опытом и предложи решения." Сравнить AI-советы с реальными результатами тестирования.
04

Домашние задания по неделям
Недели 25–27 Мини дизайн-система для своего проекта ▼
🚀
проект
Создать отдельную страницу в Figma "Design System": цветовая палитра (primary, secondary, neutral, error/success), типографическая шкала (H1–H4, body, caption, label), библиотека компонентов (кнопки, input, карточка, навбар). Всё через переменные и стили Figma.
📖
теория
Прочитать гайд по 8px Grid System. Применить к своему проекту: все отступы кратны 8 (8, 16, 24, 32, 48, 64). Использовать Layout Grid в Figma.
Недели 28–31 Hi-fi макет всего приложения ▼
🚀
главный проект
Взять Mid-fi вайрфреймы из фазы 3 и превратить в полноценный Hi-fi дизайн. Минимум 10 экранов, рабочий прототип. Применить весь арсенал: дизайн-система, компоненты, Auto Layout, правильные шрифты и цвета.
🤖
AI-задание
Использовать ChatGPT для UX Writing: "Напиши тексты для onboarding экранов приложения [описание] — 3 слайда, каждый до 20 слов, дружелюбный тон для подростков". Вставить в макет, проверить читаемость.
Недели 32–34 Доступность + тёмная тема + итог ▼
📖
теория
Изучить WCAG 2.1 основы: минимальный контраст текста 4.5:1, size кнопок min 44px. Проверить свой проект плагином Stark в Figma — исправить найденные проблемы.
✏️
практика
Добавить тёмную тему к проекту через Figma Variables (Color Tokens). Создать два режима: Light/Dark. Проверить все компоненты в обоих режимах.
05

AI-инструменты в дизайне — как ускорить работу в 3×

AI не заменяет дизайнера — он убирает скучную часть работы. Эта фаза учит использовать AI как профи: для идей, генерации UI, написания текстов и исследований. Дизайнер, умеющий работать с AI, стоит дороже.

Недели 35–40 параллельно с проектами AI-инструменты
AI-инструменты для дизайна — подробно
✨
Figma AI (Make)
↗ figma.com/ai
Встроенный AI в Figma: генерация макетов из текстового описания, замена placeholder-контента, автозаполнение данных, создание вариантов дизайна.
Когда: быстро набросать идею или заполнить макет реалистичными данными
🤖
Uizard
↗ uizard.io
Лучший для начинающих. Описываешь приложение → получаешь набор экранов. Можно загрузить скетч от руки и конвертировать в дизайн.

Портфолио — 3 кейса и выход в мир

Портфолио — главный инструмент дизайнера. Не нужно ждать "пока стану лучше". Начинать оформлять нужно прямо сейчас, с первых проектов. Хороший кейс = проблема + решение + результат, а не просто красивые скриншоты.

Недели 41–48+ параллельно с работой Behance, Figma Community
3 типа проектов для портфолио
Кейс 1 — Мобильное приложение (UX + UI)
Это главный кейс. Берём идею из Фазы 3, проходим весь путь: research → personas → wireframes → hi-fi. Показывает полный процесс мышления дизайнера.
1
Описание проблемы — 2–3 предложения: кто, зачем, почему это важно
2
Research — скриншоты интервью или опроса, Empathy Map, 2 персоны
3
User Flow + Lo-fi wireframes (фото от руки или скрин из FigJam)
4
Hi-fi дизайн — минимум 8–10 экранов с дизайн-системой
5
Результаты usability test + что изменила после фидбека
Кейс 2 — Редизайн реального продукта
Берём реальный плохой сайт/приложение (можно украинский локальный бизнес), находим проблемы и делаем лучше. Показывает критическое мышление.
1
Аудит оригинала — скриншоты + список проблем с обоснованием
2
Конкурентный анализ — как похожие продукты решают те же задачи
3
Редизайн ключевых экранов с объяснением каждого решения
4
Before/After сравнение с конкретными улучшениями
Кейс 3 — Веб-лендинг или дашборд
Лендинг для реального или вымышленного продукта. Или дашборд с данными. Показывает умение работать с вебом и информационными интерфейсами.
1
Структура через Relume AI → доработать в Figma
2
Hero-секция, features, pricing, CTA — все стандартные секции
3
Адаптив: desktop + мобильная версия
4
Опционально: сделать живым через Framer AI — настоящий сайт как портфолио

📅 Трекер задач
База данных с Tasks: название → статус (To Do / In Progress / Done) → неделя → тип (теория/практика/проект). Каждую неделю планировать заранее — что буду делать.
📚 База знаний
Конспекты всех уроков. Структура: Тема → Что узнала → Примеры → Ссылки. Со временем становится личным учебником — удобнее любого курса.
🚀 Дневник проектов
Для каждого проекта: описание → решения → фидбек → итог. Потом из этого легко писать кейс для Behance: весь контент уже есть, нужно только оформить.
🤖 Промпт-библиотека
Сохранять все AI-промпты которые сработали: для UX copy, research, генерации идей. Со временем — личная база готовых промптов для любой задачи дизайнера.
